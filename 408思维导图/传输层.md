# 传输层 — 按功能重组的思维导图

> 核心问题：**端到端怎么可靠地传数据？网络层只管"送到主机"，传输层管"送到哪个进程"并保证正确。**

---

```
                         ┌── 数据交给谁？
                         │   【端口号】16位，0~65535
                         │   服务端：知名端口 0~1023（HTTP=80, DNS=53, SMTP=25）
                         │   客户端：临时端口 49152~65535
                         │   【套接字 Socket】= IP + 端口，唯一标识网络中的一个进程
                         │
                         ├── 最简单的传法：UDP — 发出去就不管了
                         │   【特点】无连接·不可靠·无拥塞控制·首部8B
                         │   【首部字段】源端口·目的端口·长度·检验和（各2B）
                         │   【检验和】伪首部(12B)+UDP首部+数据 → 16位反码求和
                         │   【伪首部】源IP·目的IP·0·协议号17·UDP长度 → 只计算不传输
                         │   【用途】DNS·DHCP·RIP·实时音视频·多播/广播
                         │
        传 输 层           ├── TCP — 保证送到且按序、不丢、不错
       "端到端怎么可靠"      │   【特点】面向连接·可靠·全双工·字节流·有拥塞控制·首部20~60B
                         │   【首部字段】端口·序号·确认号·数据偏移·标志位·窗口·检验和·紧急指针
                         │   ★ 序号=本报文段第一个字节的编号（TCP面向字节流）
                         │   ★ 确认号=期望收到对方下一个报文段的第一个字节序号（累积确认）
                         │
                         ├── 怎么建立连接？三次握手
                         │   ① 客户端 → SYN=1, seq=x              （SYN-SENT）
                         │   ② 服务端 → SYN=1, ACK=1, seq=y, ack=x+1 （SYN-RCVD）
                         │   ③ 客户端 → ACK=1, seq=x+1, ack=y+1      （ESTABLISHED）
                         │   ★ 服务端收第三次ACK才进入ESTABLISHED
                         │   ★ 防止旧SYN导致服务端盲目分配TCB
                         │
                         ├── 怎么释放连接？四次挥手
                         │   ① 客户端 → FIN=1, seq=u               （FIN-WAIT-1）
                         │   ② 服务端 → ACK=1, seq=v, ack=u+1       （CLOSE-WAIT）
                         │   ③ 服务端 → FIN=1, ACK=1, seq=w, ack=u+1 （LAST-ACK）
                         │   ④ 客户端 → ACK=1, seq=u+1, ack=w+1     （TIME-WAIT 等 2MSL）
                         │   ★ 为什么四次？TCP全双工 → 每个方向独立关闭
                         │   ★ TIME-WAIT 2MSL：确保最后的ACK能重传 + 让旧连接报文在网络中消失
                         │
                         ├── 怎么保证可靠？
                         │   【校验和】伪首部+TCP首部+数据 → 16位反码求和
                         │   【序号】给每个字节编号 → 接收方按序号重排
                         │   【确认】累积确认 → ACK号之前全部收到
                         │   【超时重传】RTT自适应定时器 → 超时未确认则重发
                         │   【快速重传】收到3个冗余ACK → 立即重传（不等超时）
                         │
                         ├── 怎么流量控制？（接收方说了算）
                         │   【滑动窗口】接收方rwnd → 发送窗口=min(cwnd, rwnd)
                         │   ★ rwnd=0时发零窗口探测报文（坚持定时器）
                         │   【糊涂窗口】Nagle算法：凑满MSS或收到ACK再发
                         │
                         └── 怎么拥塞控制？（网络说了算）
                             【慢启动】cwnd从1开始，每RTT翻倍 → 到ssthresh
                             【拥塞避免】cwnd每RTT+1（线性增）
                             【快重传】3冗余ACK → ssthresh=cwnd/2, cwnd=cwnd/2（408简化）
                             【快恢复】收到新ACK → cwnd=ssthresh，进入拥塞避免
                             
                             状态机：慢启动 →（cwnd≥ssthresh）→ 拥塞避免
                                     任一阶段收3冗余ACK → 快重传+快恢复
                                     超时 → ssthresh=cwnd/2, cwnd=1, 重新慢启动
```

```
                         ┌── TCP 首部标志位（6个）
                         │   URG(紧急)·ACK(确认)·PSH(推送)·RST(复位)·SYN(同步)·FIN(终止)
                         │   三次握手用 SYN+ACK | 四次挥手用 FIN+ACK
         最 易 混 的       │
         三 组 对 比     ─┼── UDP vs TCP
                         │   |        |  UDP     |  TCP        |
                         │   | 连接    | 无连接    | 面向连接     |
                         │   | 可靠    | 不可靠    | 可靠交付     |
                         │   | 首部    | 8B       | 20~60B      |
                         │   | 拥塞控制 | 无       | 有           |
                         │   | 适用    | 实时/多播 | 文件/网页    |
                         │
                         └── 流量控制 vs 拥塞控制
                            流量控制：接收方瓶颈 → rwnd（点对点）
                            拥塞控制：网络瓶颈 → cwnd（全局）
                            发送窗口 = min(cwnd, rwnd)
```

```
                         ┌── 三次握手中 SYN 洪水攻击
       容 易 考 的         │   攻击者只发SYN不回复ACK → 服务器半连接队列爆满
       攻 击 与 防 护     ─┤   防御：SYN Cookie — 不分配TCB，把状态编码进seq返回
                         │
                         └── UDP 是无连接的，没有握手
                            UDP 直接发包 → 可以伪造源IP（反射放大攻击用DNS/NTP）
```

## 抄写方法

1. 中心写"传输层"，往下画两条大分支：UDP（左·简单）和 TCP（右·复杂）
2. TCP 下按"生命周期"串：三次握手 → 数据传输(可靠+流量+拥塞) → 四次挥手
3. 拥塞控制画一条"cwnd 随时间变化的曲线"，标注慢启动(指数)、拥塞避免(线性)、快重传(除2)
4. 四个窗口概念圈在一起：发送窗口、接收窗口(rwnd)、拥塞窗口(cwnd)、通知窗口——关系：发送窗口=min(cwnd, rwnd)
5. 做题碰到的端口号（HTTP=80、DNS=53 等）直接写在端口那条分支上

和课本目录的区别：目录是 UDP→TCP报文段→连接管理→可靠→流量→拥塞 的平铺，这张图是"一个 TCP 连接的一生"——从建立到传输到释放，每个阶段用到的机制自然串起来。
