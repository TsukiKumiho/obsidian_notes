# 应用层 — 按功能重组的思维导图

> 核心问题：**每个应用协议解决什么具体问题？用什么传输层协议？交互流程是怎样的？**

---

```
                         ┌── 应用怎么组织？
                         │   【C/S 模型】服务器永远在线，客户主动请求
                         │   【P2P 模型】每个节点既是客户又是服务器，可扩展性好
                         │
                         ├── DNS：域名→IP 的翻译官
                         │   【协议】UDP/53，超过512B或区域传送用TCP/53
                         │   【层次域名】根(.)→顶级(.com)→二级(baidu)→三级(www)
                         │   【域名服务器】根·顶级·权限·本地（递归从本地开始）
                         │   【解析过程】递归查询(替你查到底) vs 迭代查询(告诉你去哪查)
                         │   ★ 主机向本地DNS=递归 | 本地DNS向其他=迭代（常见配置）
                         │   【DNS缓存】每条记录有TTL，过期丢弃 → CDN调度的核心
                         │
                         ├── FTP：怎么传文件？
                         │   【协议】TCP，两条连接：
                         │   控制连接(21)：持久，传命令 → 整个会话不释放
                         │   数据连接(20)：按需建立，传数据 → 传完就断
                         │   【模式】主动(PORT)：服务器20→客户端随机端口
                         │          被动(PASV)：服务器开放随机端口，客户端去连
                         │   ★ 主动模式常被客户端防火墙拦截 → 现代FTP多用被动
                         │
        应 用 层           ├── 电子邮件：怎么发信收信？
       "应用怎么用网络"      │   【三组件】用户代理(Outlook/网页)·邮件服务器·协议
                         │   【SMTP】TCP/25，推(PUSH)，发信+服务器间转发
                         │    只传ASCII → MIME扩展支持多媒体
                         │   【POP3】TCP/110，拉(PULL)，下载到本地，默认删服务器
                         │   【IMAP】TCP/143，拉(PULL)，留服务器，多设备同步
                         │   ★ 发信用SMTP，收信用POP3或IMAP → 协议不对称！
                         │   ★ 邮件格式：信封(MAIL FROM/RCPT TO) + 首部(From/To/Subject) + 主体
                         │
                         ├── 万维网：怎么浏览网页？
                         │   【三组件】URL·HTML·HTTP
                         │   【URL格式】协议://主机:端口/路径
                         │   HTTP/1.0 → HTTP/1.1(持久连接·流水线·Host头)
                         │     → HTTP/2(二进制分帧·多路复用·服务器推送)
                         │     → HTTP/3(基于QUIC·UDP)
                         │
                         └── HTTP — 计网大题常客
                             【协议】TCP/80(HTTP) 或 TCP/443(HTTPS+TLS)
                             【无状态】服务器不记请求间关系 → Cookie补状态
                             【报文格式】请求行(GET/POST/HEAD)·首部行(Host必填)·实体主体
                             【连接】非持久(HTTP/1.0 一次一断) vs 持久(HTTP/1.1 复用TCP)
                             【流水线】持久连接下连续发请求不等响应 → 队头阻塞问题
                             【Cookie】服务器给客户端小纸条 → 下次请求带上 → 识别用户
                             【缓存】强缓存(Cache-Control/Expires) vs 协商缓存(ETag/Last-Modified)
```

```
                         ┌── DNS 递归 vs 迭代（必考示意图）
                         │   递归：A问B，B替A查到底返回结果（客户→本地DNS）
         最 易 混 的       │   迭代：A问B，B说"去问C"，A再去问C（本地DNS→根/顶级/权限）
         三 组 对 比     ─┼── HTTP 持久连接 vs 非持久连接
                         │   非持久(HTTP/1.0)：每个对象一个TCP → 2RTT+传输时间
                         │   持久(HTTP/1.1)：一个TCP传多个对象 → 省RTT
                         │   流水线持久：不等响应连续发请求 → 可能队头阻塞
                         │
                         └── SMTP vs POP3 vs IMAP
                             SMTP = 发信 + 服务器间转发（推）
                             POP3 = 下载到本地，默认看后即删
                             IMAP = 邮件在服务器，多设备同步看同一份
```

## 抄写方法

1. 中心写"应用层"，画 5 条分支：DNS、FTP、电子邮件、HTTP、应用模型(C/S+P2P)
2. DNS 画成树：根→顶级→权限→本地，标注"递归/迭代"在对应链路上
3. 电子邮件画成三人：发件人UA →(SMTP)→ 发件服务器 →(SMTP)→ 收件服务器 ←(POP3/IMAP)← 收件人UA
4. HTTP 在 C/S 模型下展开：请求报文/响应报文/Cookie/缓存/持久连接——这棵子树最大
5. 最后单画一张端口号速查表——选择题高频失分点

做题心得：应用层题分两类——纯概念题（DNS/FTP/email流程背就得分）和 HTTP 分析题（给报文截图让你分析请求方法、状态码、Cookie、缓存行为）。后一类要把 HTTP 报文格式默写熟练。
