# 数据链路层 — 按功能重组的思维导图

```
                         ┌── 怎么知道从哪到哪？
                         │   物理地址(MAC)·交换机自学习(MAC↔端口)
                         │   802.3用2个地址·802.11用4个地址
                         │
                         ├── 怎么知道一帧的开始和结束？
                         │   【字符计数法】首部写长度，一个错全乱，基本不用
                         │   【字节填充法】转义字符DLE STX/ETX，PPP用
                         │   【零比特填充法】★ 连续5个1插0，HDLC用
                         │   【违规编码法】用无效电平跳变作边界，802.3用
                         │
                         ├── 传错了怎么办？
                         │   【CRC循环冗余校验】只检错不纠错，生成多项式计算
                         │   【海明码】检2位错纠1位错，海明距离d→检d-1纠(d-1)/2
                         │   【ARQ自动重传】检到错就要求重发
                         │
                         ├── 发太快了收不下怎么办？
         数 据 链 路 层 ─┼   【停等协议】发一帧等一帧，W=1，信道利用率低
         干 了 什 么      │   【GBN后退N帧】累积确认，错一个往后全重发，W发>1 W收=1
                         │   【SR选择重传】只重传出错帧，W发=W收>1，需逐个确认
                         │
         靠 什 么 干      ├── 丢了怎么补？
                         │   【ACK/NAK确认帧】收到发ACK，出错发NAK
                         │   【超时重传】发完启动定时器，超时未收到ACK就重发
                         │   【序号机制】给每个帧编号，区分新帧和重传帧
                         │
                         ├── 多个站同时想发怎么办？
                         │   【CSMA/CD】★ 有线·先听后发·边发边听·冲突停发
                         │     争用期2τ，最小帧长=2τ×速率
                         │     截断二进制指数退避算法：k=min(重传,10)，退避时间=(2^k-1)×2τ
                         │   【CSMA/CA】★ 无线·RTS预约→CTS确认→DATA→ACK
                         │     NAV虚拟载波监听·DIFS/SIFS帧间间隔·随机退避
                         │   【令牌传递】谁拿到令牌谁发，无冲突
                         │   【信道划分】FDMA/TDMA/CDMA，预先分配，不冲突
                         │
                         ├── 连成网络后怎么管？
                         │   【以太网802.3】全双工时不用CSMA/CD，MAC帧64~1518B
                         │   【无线局域网802.11】CSMA/CA，4地址字段，AP/BSS/ESS
                         │   【VLAN 802.1Q】插入4B标签，Access口去标签/Trunk口留标签
                         │   【STP生成树协议】选根桥→选根端口→选指定端口→阻塞其余
                         │
                         └── 用什么设备？
                             【集线器】物理层，不隔冲突不隔广播，共享带宽
                             【网桥】链路层，连接两个同类型LAN，隔冲突不隔广播
                             【交换机】多端口网桥，自学习(MAC↔端口)，未知MAC→泛洪
                               直通交换：读6B目的MAC即转发，快但可能有错帧
                               存储转发：收全帧验CRC再发，慢但可靠
                             【路由器】网络层，隔冲突也隔广播
```

## 抄写方法

这张图不是让你一次抄完的。画法：

1. 中心写"数据链路层"，画 6 条分支对应上面 6 个问题（不是 8 个章节）
2. 每学完一个子节，在对应分支上补一两笔——不追求一次画全
3. 做题碰到哪个概念混淆了，回来在这张图上圈出来——这才是这张图的价值
4. 考前这张 A4 应该是密密麻麻但你自己完全看得懂的

和课本目录的区别：目录告诉你"3.4 讲了滑动窗口"，这张图告诉你"滑动窗口是解决'发太快'的，三个协议的区别是窗口大小和确认方式"。前者是存储，后者是理解。
