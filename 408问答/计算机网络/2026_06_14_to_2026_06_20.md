## Q1 · 数据报、分组交换与虚电路的区别

> 数据报和分组交换以及虚电路的区别是什么？

**答：三者分属不同层级——分组交换是宏观的数据交换方式，数据报和虚电路是分组交换的两种具体实现服务。**

### 一、概念层级关系

```text
数据交换方式
    ├── 电路交换（Circuit Switching）
    │       └── 建立物理连接 → 通信 → 释放连接
    │
    └── 分组交换（Packet Switching）
            ├── 数据报服务（Datagram Service）
            │       └── 每个分组独立选路，无连接
            │
            └── 虚电路服务（Virtual Circuit Service）
                    └── 先建立逻辑连接，分组沿同一路径转发
```

### 二、核心定义速查

| 概念 | 一句话定义 | 归属层级 |
| :--- | :--- | :--- |
| **分组交换** | 将报文拆分为分组（包），以分组为单位存储转发的交换方式 | 数据交换方式（宏观） |
| **数据报服务** | 每个分组独立携带完整目的地址，网络层为每个分组**独立选路** | 网络层提供的无连接服务 |
| **虚电路服务** | 通信前建立逻辑连接（虚电路号），所有分组沿**同一路径**转发，通信后释放 | 网络层提供的面向连接服务 |

### 三、分组交换 vs 电路交换

| 对比维度 | 电路交换 | 分组交换 |
| :--- | :--- | :--- |
| **连接建立** | 需要（物理连接） | 可选（数据报无需，虚电路需要逻辑连接） |
| **资源分配** | 独占资源（专用链路） | 统计复用（共享链路） |
| **传输单位** | 比特流 | 分组（包） |
| **转发依据** | 不需转发（专线直通） | 每个分组按头部地址存储转发 |
| **延迟** | 建立连接慢，传输延迟稳定 | 每个节点有排队延迟 |
| **链路利用率** | 低（空闲时也无法给他人用） | 高（统计时分复用） |
| **典型场景** | 传统电话网 | 互联网（IP） |

### 四、数据报服务 vs 虚电路服务（核心对比）

| 对比维度 | 数据报服务（Datagram） | 虚电路服务（Virtual Circuit） |
| :--- | :--- | :--- |
| **连接建立** | 不需要 | **必须先建立**逻辑连接 |
| **通信释放** | 不需要 | 需要释放 |
| **目的地址** | 每个分组携带**完整目的地址** | 分组只携带**虚电路号**（短标识符） |
| **路由决策** | 每个分组在各节点**独立选路** | 仅在建立阶段选路一次，后续分组沿**同一路径** |
| **分组到达顺序** | 可能乱序（不同路径延迟不同） | **按序到达**（同一条路） |
| **节点故障** | 可自动绕行（健壮） | 整条虚电路中断，需重建 |
| **差错控制** | 由主机（传输层）负责 | 网络层可提供一定保证 |
| **流量控制** | 网络层不负责 | 网络层可提供 |
| **典型实现** | **IP 协议**（互联网） | **ATM、帧中继、X.25** |
| **设计哲学** | 复杂留终端，网络做最简单的事 | 网络负责可靠性，终端简化 |

### 五、核心区别图解

```
【数据报服务】
主机A ───→ 路由器1 ───→ 路由器2 ───→ 主机B
              │                 ↑
              └──→ 路由器3 ───→─┘
              
每个分组独立选路：分组1走 1→2→B，分组2可能走 1→3→2→B
→ 可能乱序到达，但若节点2故障，可自动绕行到1→3→B


【虚电路服务】
主机A ───→ 路由器1 ───→ 路由器2 ───→ 主机B
            ↑ 建立阶段：    ↑
            分配VC号=5      转发表: 入(VC=5,端口1)→出(VC=7,端口2)
            
所有数据分组沿同一路径：
分组1(A,VC=5) → 分2(A,VC=5) → ... → 全部在B按序接收
→ 若路由器2故障，整条虚电路中断，需重新建立
```

### 六、深层辨析：数据报不是"分组交换"的同义词

| 命题 | 判定 | 原因 |
| :--- | :---: | :--- |
| "分组交换就是数据报" | × | 分组交换包含数据报和虚电路两种服务 |
| "虚电路 = 电路交换" | × | 虚电路逻辑上类似电路，但底层仍是**分组交换（统计复用）** |
| "数据报一定乱序" | × | 可能不乱序，只是**不保证**顺序 |
| "虚电路有连接 = TCP 是虚电路" | × | TCP 是**传输层**面向连接；虚电路是**网络层**服务。两者层次不同 |
| "IP 提供虚电路服务" | × | IP 提供的是**数据报服务**（无连接） |

### 七、408 高频考察角度

| 考察角度 | 常考问法 | 关键答案 |
| :--- | :--- | :--- |
| 概念归属 | "IP 属于哪种交换方式/服务？" | 分组交换 + 数据报服务 |
| 对比选择 | "哪种服务不需要建立连接？" | 数据报 |
| 路由灵活性 | "某节点故障后，哪种服务能自动恢复？" | 数据报（每个分组独立选路可绕行） |
| 虚电路号的局部性 | "虚电路号是全局唯一的吗？" | 不是——仅**逐段链路**局部有效，每段可重新编号 |
| 体系结构归属 | "虚电路的差错控制在哪一层？" | 网络层（虚电路网络内部），不同于 TCP（传输层端到端） |

### 八、速记口诀

```text
电路交换先搭桥，独占资源效率低
分组交换分拆包，统计复用不浪费
数据报是独立走，各寻各路可绕行
虚电路先开通道，同路有序易断线
IP 走的是数据报，ATM/X.25 虚电路
```

> **省流：** 分组交换是宏观交换方式（与电路交换对应），数据报和虚电路是分组交换的两种服务——数据报无连接（每个分组独立选路，可乱序，健壮，IP 即此），虚电路面向连接（先建逻辑连接，同路有序，易中断，ATM/X.25 即此）。"虚电路 ≠ 电路交换"——虚电路底层仍是分组交换的统计复用。

## Q2 · 奈奎斯特准则与香农定理（计算题全攻略）

> 奈奎斯特准则和香农定理的区别是什么？在计算题中有哪些注意事项？当同时出现了波特率/比特率之比以及信噪比（即不是理论环境）时，是否可以使用奈奎斯特准则？如果还出现了采样频率，该如何考虑？

**答：奈奎斯特管"码元速率天花板"（无噪声物理约束），香农管"噪声下的信息速率天花板"。两者不是替代关系——有噪声时实际极限 = min(奈奎斯特上限, 香农上限)。采样频率属于奈奎斯特采样定理（PCM编码体系），与信道容量准则独立。**

### 一、核心定义速查

| 定理 | 一句话 | 核心公式 | 使用条件 |
| :--- | :--- | :--- | :--- |
| **奈奎斯特准则** | 在**无噪声**的带宽受限信道中，**码元速率有上限** | $C = 2W \log_2 V$ | 理想信道（无噪声） |
| **香农定理** | 在**有噪声**的带宽受限信道中，**信息速率有上限** | $C = W \log_2(1 + S/N)$ | 有高斯噪声的信道 |

> **核心区别**：奈奎斯特管"码元速率的天花板"（无噪声也有上限，因为带宽限制了码元宽度）；香农管"噪声下的信息速率天花板"。

### 二、公式拆解与关键参数

#### 2.1 奈奎斯特准则

$$C = 2W \cdot \log_2 V$$

| 符号 | 含义 | 单位 | 常见陷阱 |
| :--- | :--- | :--- | :--- |
| $W$ | 信道带宽 | Hz | 题目可能给 kHz/MHz，需统一单位 |
| $V$ | 信号离散等级数（码元种类数） | 个 | 若给"每个码元携带 $k$ 比特"，则 $V = 2^k$ |
| $2W$ | 最高码元速率（波特率） | Baud | **奈奎斯特频率 = 2W，与 $V$ 无关** |
| $\log_2 V$ | 每码元携带比特数（比特/码元比） | bit/符号 | 当 $V=2$ 时，$\log_2 2 = 1$ |

> 奈奎斯特公式 = **波特率 × 每码元比特数** = $2W \times \log_2 V$

#### 2.2 香农定理

$$C = W \cdot \log_2(1 + \frac{S}{N})$$

| 符号 | 含义 | 单位 | 常见陷阱 |
| :--- | :--- | :--- | :--- |
| $W$ | 信道带宽 | Hz | 同上 |
| $S/N$ | 信噪比（**功率比，无量纲**） | — | **题目给 dB 必须先转换！** |
| $S$ | 信号平均功率 | W | — |
| $N$ | 噪声平均功率 | W | — |

> 提示：dB 转换公式：$\text{dB} = 10\log_{10}(S/N)$，即 $S/N = 10^{\text{dB}/10}$

### 三、两者同时出现的计算题——核心解题框架

```
已知：带宽 W，信号等级 V（或每码元 k 比特），信噪比 S/N（或 dB 值）
求：信道的最大数据传输速率

步骤①：算奈奎斯特上限
    C_奈 = 2W × log₂V
    （若无噪声理想环境，这就是最终答案）

步骤②：算香农上限
    C_香 = W × log₂(1 + S/N)
    （注意 dB → 功率比的转换）

步骤③：取较小值
    实际最大速率 = min(C_奈, C_香)
    因为：香农管噪声上限，奈奎斯特管码元速率上限
    信道实际传输能力不能超过任何一个

步骤④：检查是否问"最大比特率"还是"最大波特率"
    - 波特率 = 2W（仅由带宽决定，与 V 和噪声无关）
    - 比特率 = min(奈奎斯特比特率, 香农比特率)
```

#### 实例演示

> 已知带宽 3kHz，信噪比 30dB，采用 8 种相位调制（$V = 8$）。求最大数据传输速率。

```
① 奈奎斯特：C_奈 = 2 × 3000 × log₂8 = 6000 × 3 = 18000 bps
② 香农：S/N = 10^(30/10) = 1000
   C_香 = 3000 × log₂(1+1000) = 3000 × log₂1001 ≈ 3000 × 9.97 ≈ 29910 bps
③ min(18000, 29910) = 18000 bps
④ 答：最大 18000 bps（奈奎斯特更紧）
```

### 四、非理想环境下能否使用奈奎斯特？

**答：可以，而且必须用——但用法不同。**

| 场景                        | 奈奎斯特怎么用                   | 香农怎么用                         | 最终答案          |
| :------------------------ | :------------------------ | :---------------------------- | :------------ |
| 仅给带宽 + 信号等级（理论无噪声）        | **直接用** $C = 2W \log_2 V$ | 不适用（无噪声数据）                    | 奈奎斯特值         |
| 仅给带宽 + 信噪比（理论有噪声，没给信号等级）  | 不适用（不知道 $V$）              | **直接用** $C = W \log_2(1+S/N)$ | 香农值           |
| **两者都给了**（带宽 + $V$ + SNR） | 算奈奎斯特上限                   | 算香农上限                         | **min(奈, 香)** |
| 给了波特率 + $V$ + SNR         | $C_奈 = 波特率 × \log_2 V$    | 正常算                           | **min(奈, 香)** |

> 关键认知：奈奎斯特给出的是**码元速率上限**，这是物理约束——即使没有噪声，你也不能在一个 3kHz 的信道上每秒传输超过 6000 个码元（$2W=6000$ 波特）。噪声的存在不会改变这个物理约束，所以**有噪声时奈奎斯特仍然适用**，只不过噪声可能让极限更低。

### 五、采样频率出现时的处理

采样频率出现时，**通常是在考察 PCM 编码的计算题**，涉及的是**奈奎斯特采样定理**（不同于奈奎斯特信道容量准则）。

#### 5.1 奈奎斯特采样定理（不要与上面的混淆！）

| 项目         | 奈奎斯特信道容量准则        | 奈奎斯特采样定理            |
| :--------- | :---------------- | :------------------ |
| **公式**     | $C = 2W \log_2 V$ | $f_s \ge 2f_{\max}$ |
| **作用**     | 求信道最大数据传输速率       | 求不失真重建信号所需的最低采样频率   |
| **应用场景**   | 信道容量计算            | PCM 编码 / 模数转换       |
| **$W$ 含义** | 信道带宽              | 信号最高频率 $f_{\max}$   |

#### 5.2 PCM 计算题的完整链路

```
模拟信号（最高频率 f_max）
    │
    ▼ 采样（f_s ≥ 2f_max）         ← 奈奎斯特采样定理
    │
    ▼ 量化（N 个量化等级）           ← 每个样点需 ⌈log₂N⌉ 比特
    │
    ▼ 编码 → PCM 数字信号
    │
    ▼ 传输 → 信道（带宽 W, 可能有噪声）
    │
    ▼ 数据速率 = f_s × ⌈log₂N⌉      ← 这是 PCM 输出比特率
```

#### 5.3 采样频率相关的典型题目结构

```
题目给：信号最高频率 f_max，量化等级 N，信道带宽 W，信噪比 SNR

计算步骤：
① 最低采样频率 f_s = 2f_max                    （奈奎斯特采样定理）
② PCM 数据速率 = f_s × ⌈log₂N⌉                 （= 每秒采 × 每样比特）
③ 奈奎斯特信道上限 C_奈 = min(2W log₂V, ②产生的速率)
   香农信道上限 C_香 = W log₂(1+S/N)
④ 信道能否传输？ → PCM 速率 ≤ min(C_奈, C_香) 才可行
```

### 六、常见陷阱与避坑清单

| 陷阱 | 正确做法 |
| :--- | :--- |
| dB 直接代入公式 | **必须先转功率比**：$S/N = 10^{\text{dB}/10}$ |
| 把 $\log_{10}$ 当 $\log_2$ | 香农和奈奎斯特的 log 都是 **$\log_2$**；$\log_2 x = \frac{\log_{10} x}{\log_{10} 2} \approx 3.32 \log_{10} x$ |
| 混淆 $2W$（奈奎斯特频率）和 $W$ | 奈奎斯特码元速率上限 = $2W$ 波特（**系数是 2**）；香农公式系数是 $W$（**系数是 1**） |
| $V$ 和 $k$ 不转换 | 若题给"每码元 $k$ 比特"，则 $V = 2^k$；$\log_2 V = k$ |
| 忘记取 min | 两者都给时，最终答案 = **min(奈奎斯特, 香农)**，不可只算一个 |
| 采样频率 $f_s$ 和信道带宽 $W$ 混用 | $f_s$ 属于采样定理（信号处理），$W$ 属于信道容量（通信），两套独立体系 |
| 误以为有噪声就不能用奈奎斯特 | 奈奎斯特码元速率上限 $2W$ **不受噪声影响**，有噪声时比特率上限取 min |

### 七、408 常考题型

| 题型       | 典型设问                                     | 答题关键                                                       |
| :------- | :--------------------------------------- | :--------------------------------------------------------- |
| 纯奈奎斯特    | "无噪声信道，带宽 4kHz，16 种信号等级，求最大速率"           | $2 \times 4000 \times \log_2 16 = 32000$ bps               |
| 纯香农      | "带宽 3kHz，信噪比 30dB，求最大速率"                 | 先 $S/N = 1000$，再 $3000 \times \log_2 1001 \approx 30$ kbps |
| 两者结合     | "16 相调制 + 30dB 信噪比 + 3kHz 带宽，求最大速率"      | min(奈, 香)，奈 = 24kbps, 香 ≈ 30kbps → 24kbps                  |
| PCM + 信道 | "采样频率 8kHz，256 级量化，带宽 20kHz 无噪声，信道能否传输？" | PCM 速率 = 8000×8 = 64kbps；C_奈 = 2×20000 = 40kbps < 64k → 不能 |

### 八、速记口诀

```
奈奎斯特管码元，波特率是两倍宽
香农管的是噪声，信噪比要化功率
两者都给取最小，dB 必须先转换
采样定理是另一码，f_s 大于两倍 f
```

### 九、关键术语辨析：题目中的"信号描述"怎么翻译成 $V$

| 题目用语 | 含义 | $V$ 值 | $\log_2 V$ |
| :--- | :--- | :---: | :---: |
| **"二进制信号"** | 每个码元只有两种状态（0 和 1） | **2** | **1** |
| **"四进制信号"** / "4 种相位" / "QPSK" | 4 种离散状态 | 4 | 2 |
| **"八进制信号"** / "8 种相位调制" | 8 种离散状态 | 8 | 3 |
| **"16-QAM"** / "16 种幅度/相位组合" | 16 种离散状态 | 16 | 4 |
| **"每个码元携带 $k$ 比特"** | $V = 2^k$ | $2^k$ | $k$ |
| **"四相调制"（如 QPSK）** | 4 种相位 = 4 种码元 | 4 | 2 |
| **"8PSK"** | 8 种相位 | 8 | 3 |

> **核心结论**：题目说"二进制信号"→ $V=2$ → $\log_2 V = 1$ → 此时**比特率 = 波特率**（一个码元恰携带 1 比特）。这是奈奎斯特公式的最简形式：$C = 2W$。

> **省流：** 奈奎斯特（$C=2W\log_2 V$）管码元速率上限——无噪声物理约束，有噪声仍适用；香农（$C=W\log_2(1+S/N)$）管噪声下信息速率上限。两者同时出现取 min。采样频率 $f_s\ge 2f_{\max}$ 属于 PCM 编码体系（奈奎斯特采样定理），与信道容量准则独立——先由 $f_s \times$ 量化比特得 PCM 速率，再与信道容量 min(奈,香) 比较判断能否传输。

## Q3 · 数据帧出错/丢失与确认帧的关系——不可检测错误辨析

> 数据帧出错或丢失，其中出错会产生错误的确认帧吗？即出错后的数据帧变成了接收方可以接受的另外的数据帧的情况。

**答：数据帧出错 ≠ 产生错误确认帧。正常情况：CRC 校验失败 → 帧被丢弃 → 不发任何 ACK → 发送方超时重传。但不可检测错误（$G(x) \mid E(x)$）理论上能让错误帧伪装成另一有效帧被接收——概率极低但非零。**

### 一、正常情况：数据帧出错 → 不产生任何确认帧

```
发送方                         接收方
  │                              │
  ├──── 数据帧(seq=0) ──────────→│
  │                              │  CRC 校验 × 失败
  │                              │  帧被丢弃
  │                              │  不发送 ACK
  │                              │
  │  ← 超时计时器到期 ←          │
  │                              │
  ├──── 数据帧(seq=0) 重传 ─────→│
  │                              │  CRC √
  │←──── ACK(seq=0) ────────────┤
```

> **核心结论：数据帧出错 → CRC 校验失败 → 帧被丢弃 → 不发送任何确认帧。** 接收方不会因为收到错误帧而发送一个"错误"的 ACK，而是**根本不发 ACK**。发送方通过超时机制发现并重传。

### 二、不可检测错误——这才是真正的关键

**问题原文：** "出错后的数据帧变成了接收方可以接受的另外的数据帧"

**答：这种情况在理论上存在，称为"不可检测错误"（Undetectable Error）。**

#### 2.1 错误检测的本质

任何一个错误检测码（含 CRC）都有这样一个数学性质：

```text
所有可能的比特串（2^n 种）
    ├── 有效码字（满足校验规则，约 2^(n-k) 种）
    └── 无效码字（不满足校验规则）
```

- **可检测错误**：错误把有效码字 A 变成了**无效码字** → CRC 校验失败 → 帧被丢弃
- **不可检测错误**：错误把有效码字 A 变成了**另一个有效码字 B** → CRC 校验通过 → 帧被当作 B 接收！

#### 2.2 不可检测错误发生的数学条件（CRC）

设发送的比特序列为 $T(x)$（已包含 CRC 冗余码），信道产生的差错模式为 $E(x)$（差错位 = 1，正确位 = 0），则接收方收到的序列为：

$$R(x) = T(x) \oplus E(x)$$

接收方用生成多项式 $G(x)$ 除以 $R(x)$，校验失败的条件是 $G(x) \nmid R(x)$，即 $G(x) \nmid E(x)$。

> **不可检测错误发生的充要条件：$G(x) \mid E(x)$**，即差错多项式恰好能被生成多项式整除。

#### 2.3 这意味着什么？

```
发送方发出：  [ 数据=0x1234 | CRC=0xABCD ]  ← 有效码字 A
                             │
               信道比特出错（某些位翻转）
                             │
                             ▼
接收方收到：  [ 数据=0x5678 | CRC=0xEF01 ]  ← 有效码字 B（碰巧CRC也对了！）
                                                    ↑
                                    接收方校验通过，错误的数据被上交到网络层
```

**这种错误的帧数据被当作正确数据接收，但不会产生"错误的确认帧"**——接收方正常发送 ACK，因为它认为自己收到了一个正确的帧，只是帧的内容已经不是发送方原本想发的了。

### 三、区分四种情况（全量对比）

| 情况 | 数据帧状态 | 接收方行为 | 是否产生 ACK | 最终结果 |
| :--- | :--- | :--- | :---: | :--- |
| **无误** | CRC 校验通过，内容正确 | 接受帧，上交网络层 | 是（正常 ACK） | 正确交付 |
| **可检测错误** | CRC 校验失败 | **丢弃帧** | **否**（不发 ACK） | 发送方超时重传 |
| **不可检测错误** | CRC 碰巧也通过，但内容已错 | 接受帧（以为是正确的） | 是（正常 ACK） | **错误数据被上交** |
| **帧丢失** | 根本没到 | — | 否 | 发送方超时重传 |

> 关于"错误的确认帧"：真正能产生"错误 ACK"的，不是数据帧出错，而是 **ACK 帧本身在返回途中出错或丢失**——但这又回到了重复帧和序列号管理的范畴（停等协议/连续 ARQ 中已讨论）。

### 四、CRC 对不可检测错误的防护能力

| 错误类型 | CRC 能否检测 | 条件 |
| :--- | :---: | :--- |
| 所有单个比特错误 | 能 | $G(x)$ 至少有两项 |
| 所有两个比特错误 | 能 | $G(x)$ 不含 $(x+1)$ 因子的条件下，在特定范围内 |
| 所有奇数个比特错误 | 能 | $G(x)$ 含因式 $(x+1)$ |
| 所有长度 $\le r$ 的突发错误 | 能 | $r$ = 生成多项式次数（CRC-32: $r=32$） |
| 长度 $> r$ 的突发错误 | 不能全部检测 | 漏检概率 $\approx 2^{-r}$ |
| **恰好把有效码字变成另一有效码字** | **不能** | $G(x) \mid E(x)$ |

> CRC-32 的漏检概率约 $2^{-32} \approx 2.3 \times 10^{-10}$，这意味着差错模式恰好被 $G(x)$ 整除的概率极低。

### 五、408 真题考察角度

| 考察角度 | 典型问法 | 关键答案 |
| :--- | :--- | :--- |
| 检错码原理 | "CRC 能否检测所有错误？" | 不能——不可检测错误发生在 $G(x) \mid E(x)$ 时 |
| 差错-确认关系 | "数据帧出错后接收方会回复 NAK 吗？" | 取决于协议：停等 ARQ 通常不发 NAK 而靠超时；连续 ARQ 可选择发 NAK/REJ |
| CRC 检测能力 | "CRC 能检测所有奇数位错误吗？" | 当 $G(x)$ 含 $(x+1)$ 因式时，可以 |
| 不可检测错误概率 | "为什么 CRC-32 的漏检率极低？" | $2^{-32}$，且实际中突发错误的差错模式几乎不可能恰好被 $G(x)$ 整除 |
| 帧格式中类型字段的作用 | "为什么数据帧和 ACK 帧不会混？" | 帧头部有类型字段（Type），错误比特翻转同时改变类型字段且 CRC 仍正确的概率几乎为零 |

### 六、速记总结

```
帧出错 → CRC 败 → 帧丢弃 → 不发 ACK → 超时重传
     ↘ CRC 碰巧过（不可检测错误）→ 错误数据被当作正确接收 → 照样发 ACK
     
"错误的确认"不是出错帧产生的——
ACK 本身出错/丢失才会造成重传和重复帧问题
不可检测错误是 CRC 的数学盲区，但概率极低
```

> **省流：** 数据帧出错 ≠ 产生错误确认帧。正常情况：CRC 校验失败 → 帧被丢弃 → 不发任何 ACK → 发送方超时重传。不可检测错误（$G(x) \mid E(x)$）理论上能让错误帧伪装成另一有效帧被接收，CRC-32 概率约 $2^{-32}$，可忽略但不为零。真正会引起"确认混乱"的是 ACK 帧自身出错/丢失，而非数据帧出错。

## Q4 · 滑动窗口的双向滑动规则——发送方 vs 接收方（GBN/SR）

> 对于窗口滑动的情况中，是否接受方是收到了最前面的帧，而发送方是收到最前面的帧的确认帧。比如在后退N帧协议中，每当接收方确认一个帧，返回确认帧并被发送方接受到时，发送方就会立马滑动一格窗口。

**答：核心理解正确，但需修正一个关键细节——GBN 中发送方收到累积 ACK 后，窗口不一定只滑一格，可能一次滑多格。**

### 一、核心规则速查

| 角色 | 窗口滑动的触发条件 | 滑动多少 | 关键机制 |
| :--- | :--- | :--- | :--- |
| **接收方（GBN）** | 收到**按序到达**的帧（seq = expected_seq） | 每次滑 1 格 | 只收按序帧，乱序丢弃 |
| **发送方（GBN）** | 收到**累积 ACK**，确认号覆盖了最早未确认帧 | **可能滑多格**（累积确认效应） | ACK=k 意味着 0~k 全部已收 |
| **发送方（SR）** | 最早未确认帧的 ACK 到达 | 向前滑到下一个未确认帧为止 | 非累积 ACK，每帧独立确认 |

### 二、逐帧收发：你的理解完全正确（滑一格）

**在 GBN 逐帧发送的正常情况下，确实每次 ACK 回来窗口滑一格：**

```
发送方窗口 [0,1,2,3]                 接收方 expected_seq=0
    │
    ├── 帧0 ──→ 收到帧0，expected_seq→1，回 ACK0
    │←── ACK0 ─┤
    │
窗口滑至 [1,2,3,4]   ← 滑了一格
    │
    ├── 帧1 ──→ 收到帧1，expected_seq→2，回 ACK1
    │←── ACK1 ─┤
    │
窗口滑至 [2,3,4,5]   ← 又滑了一格
```

### 三、但 GBN 可以一次滑多格——累积 ACK 的力量

**GBN 采用累积确认**：ACK=k 的含义不是"我收到了帧 k"，而是"帧 0 ~ 帧 k **全部正确收到**"。

```
发送方窗口 [0,1,2,3]  (窗口大小 = 4)    接收方 expected_seq=0
    │
    ├── 帧0 ──→ 收到帧0，expected_seq→1，回 ACK0
    ├── 帧1 ──→ 收到帧1，expected_seq→2，回 ACK1
    ├── 帧2 ──→ 收到帧2，expected_seq→3，回 ACK2
    ├── 帧3 ──→ 收到帧3，expected_seq→4，回 ACK3
    │
    │←── ACK0 到达 ─┤  窗口滑至 [1,2,3,4]
    │←── ACK1 到达 ─┤  窗口滑至 [2,3,4,5]
    │←── ACK2 丢失！  │
    │←── ACK3 到达 ─┤
    │                    ↑ ACK3 是累积确认：表示 0,1,2,3 全部收到
    │                      窗口直接从 [2,3,4,5] 滑至 [4,5,6,7]
    │                      ACK2 丢失也不影响——ACK3 已经替它确认了！
```

| 场景 | 窗口滑动量 |
| :--- | :---: |
| 每发一帧等一个 ACK（停等方式） | 每次 1 格 |
| 连续发送，ACK 逐个回来且都收到 | 每次 1 格 |
| 连续发送，前面某个 ACK 丢失但后面 ACK 到达 | **一次滑多格**（累积确认补上） |
| 连续发送，只收到最后一个 ACK | **一次滑多格**（直接跳到已确认位置） |

### 四、接收方：恰好相反——必须按序接收，每次只滑一格

```
接收方 (GBN: 实际只有 expected_seq 这一个"窗口边界")

expected_seq = 0

收到帧0 → 匹配！→ 上交网络层 → expected_seq = 1
收到帧1 → 匹配！→ 上交网络层 → expected_seq = 2
收到帧3 → 不匹配(expected=2) → 丢弃！→ expected_seq 仍为 2
                              → 发送 ACK1（重复确认帧1）
收到帧2 → 匹配！→ 上交网络层 → expected_seq = 3
          → 发送 ACK2（帧3之前已被丢弃，需发送方重传）
```

> **接收方 GBN 的窗口滑动逻辑**：只有当 `seq == expected_seq` 时才收帧 + 窗口滑 1 格。绝不会因为收到后面的帧而跃过多格——乱序帧直接丢弃。

### 五、发送方 vs 接收方——核心对比

| 对比维度 | 发送方（GBN） | 接收方（GBN） |
| :--- | :--- | :--- |
| **窗口滑动触发信号** | 收到 ACK（累积确认号 ≥ 窗口下沿） | 收到帧（seq = expected_seq） |
| **每次滑动量** | **不固定**——取决于累积 ACK 确认了多少帧 | **固定 1 格**——只接受按序到达的下一帧 |
| **乱序到达行为** | ACK 可以乱序到达（后续 ACK 覆盖之前的） | 帧**不能**乱序接受——乱序直接丢弃 |
| **丢 ACK 的影响** | 通常无影响——后续累积 ACK 会补上 | —（接收方不发帧） |
| **丢帧的影响** | 超时重传，窗口回退到未确认帧 | expected_seq 卡住，后续正确帧也丢弃 |

### 六、修正你的描述——更精确的表述

> 你的原话："每当接收方确认一个帧，返回确认帧并被发送方接受到时，发送方就会立马滑动一格窗口"

**更精确的表述：**

```
接收方：收到最前面的帧 → 滑一格（固定）
发送方：收到最前面的帧的确认帧（累积 ACK）→ 滑到已被确认的最远位置（可能不止一格）
```

> "滑一格"在逐帧收发时对，但不能解释 GBN 累积 ACK 一次滑多格的能力。GBN 发送方窗口滑动的本质是：**窗口下沿 = 最大已收到累积 ACK 号 + 1**。

### 七、SR（选择重传）的差异速览

| 对比维度 | GBN | SR |
| :--- | :--- | :--- |
| 接收方窗口滑动 | 按序收到才滑，每次 1 格 | 可收乱序帧并缓存；当最早缺失帧到达时，一次性滑过多格（连同缓存中连续帧一起上交） |
| 发送方窗口滑动 | 累积 ACK → 可能一次滑多格 | 非累积 ACK → 只有最早未确认帧的 ACK 到达才滑（但可能连续滑过多格，因多个帧的 ACK 可能已先到达） |
| ACK 语义 | "帧 k 及之前全部收到" | "帧 k 已收到"（独立确认） |

### 八、速记口诀

```
接收方：按序收一帧，窗口滑一格
发送方：累积 ACK 到，窗口跳到确认后
GBN 窗滑不固定，一个 ACK 过三格
SR 各帧独立认，下沿到了才拉动
```

> **省流：** 理解方向正确——接收方收到按序帧滑一格，发送方收到 ACK 后窗口前移。但 GBN 的累积 ACK 意味着发送方窗口可能一次滑多格（ACK=k 确认了 0~k 全部帧），这是累积确认的核心威力。接收方 GBN 严格按序，每次只滑一格，乱序帧直接丢弃。

## Q5 · 连续 ARQ 信道利用率——GBN vs SR

> 对于连续 ARQ 协议的信道利用率的计算，GBN 协议和 SR 协议的计算有什么区别？但从图像上来看我觉得两者没有区别，都是流水线形式的传输方式。

**答：直觉正确——流水线形态上两者完全相同。区别不在"正常跑"的时候，而在"出错后"的重传代价上：GBN 一次出错重传 W 帧，SR 只重传 1 帧，利用率差了一个分母因式。**

### 一、无差错时：完全相同

在信道没有出错的情况下，GBN 和 SR 的信道利用率公式一模一样：

$$U = \begin{cases} \dfrac{W}{1+2a} & \text{当 } W < 1+2a \\[6pt] 1 & \text{当 } W \ge 1+2a \end{cases}$$

其中 $a = \dfrac{T_P}{T_F}$（传播时延与发送时延之比）。

> 无差错时两者都只是"把窗口塞满管道"，窗口够大就能达到 100% 利用率。这正是你说的"图像上看没有区别"的原因。

### 二、有差错时：分道扬镳

一旦发生帧出错/丢失，两者的重传范围不同，利用率开始分化：

| 协议 | 出错后重传范围 | 每错误代价 | 利用率 |
| :--- | :--- | :---: | :--- |
| **GBN** | 重传错误帧 **及之后所有已发送帧**（最多 $W$ 帧） | 大 | 低（更差） |
| **SR** | **仅重传出错的那一帧** | 小（1 帧） | 高（更好） |

#### 2.1 GBN 有差错利用率

设 $P_f$ 为帧出错概率。GBN 每次出错平均要重传的帧数近似为 $\frac{W}{2}$（出错时窗口内尚未 ACK 的帧约有一半已发出）：

$$U_{\text{GBN}} = \frac{W}{1+2a} \cdot \frac{1-P_f}{1 + (W-1)P_f}$$

> 分母 $(W-1)P_f$ 就是 GBN 的额外代价——出一次错要多传很多帧。

#### 2.2 SR 有差错利用率

$$U_{\text{SR}} = \frac{W}{1+2a} \cdot (1-P_f)$$

> 只乘以 $(1-P_f)$，因为出错只重传 1 帧，效率损失仅来源于重传率本身。

### 三、为什么图像上看不出区别

```
时间 →
GBN:
|帧0|帧1|帧2|帧3|帧4|帧5|帧6|帧7|帧2|帧3|帧4|帧5|帧6|帧7|
         ↑                                               ← 帧2出错，重传2~7（浪费6帧）

SR:
|帧0|帧1|帧2|帧3|帧4|帧5|帧6|帧7|帧2|
         ↑                       ← 帧2出错，只重传帧2（浪费1帧）
```

> 两者的流水线形态确实一样——都是连续发送。但在**占用信道的时间比例**上，GBN 因为一次错要重传一堆，相同的错误率下浪费了更多信道时间。

### 四、核心对比速查

| 对比维度 | GBN | SR |
| :--- | :--- | :--- |
| **无差错利用率公式** | $U = \min(\frac{W}{1+2a}, 1)$ | **相同** $U = \min(\frac{W}{1+2a}, 1)$ |
| **有差错利用率公式** | $U = \frac{W}{1+2a} \cdot \frac{1-P_f}{1+(W-1)P_f}$ | $U = \frac{W}{1+2a} \cdot (1-P_f)$ |
| **出错时重传帧数** | 错误帧 + 后续 $W-1$ 帧（最坏） | 仅 1 帧 |
| **$P_f$ 升高时利用率下降** | **急剧下降**（分母也变大） | 线性下降 |
| **接收方缓存要求** | 无需缓存乱序帧 | 需要缓存乱序帧 |
| **流水线形态** | 连续发送 | 连续发送（**相同**） |

> **困惑的根源**：流水线的"形状"一样 ≠ 花在有用数据上的时间比例一样。GBN 把信道时间花在了大量重传上，SR 只花在出错的那一帧上——利用率差了一个因子 $\frac{1}{1+(W-1)P_f}$。

### 五、408 计算题中的典型差异

```
题目：W = 7，a = 2（即 1+2a = 5），P_f = 0.1，每帧发送时间 T_F，求最大信道利用率。

【GBN】U = (7/5) × (1-0.1) / (1+6×0.1) = 1.4 × 0.9 / 1.6 = 1.26 / 1.6 = 0.7875

【SR】U = (7/5) × (1-0.1) = 1.4 × 0.9 = 1.26 → 但 W ≥ 1+2a 时：U_SR = 1-P_f = 0.9

相同条件下：GBN = 0.56，SR = 0.9，GBN 利用率仅为 SR 的 62%。
```

### 六、408 经典陷阱

| 陷阱 | 正确认知 |
| :--- | :--- |
| "GBN 和 SR 利用率一样" | 无错时一样，有错时 GBN < SR（差距随 W 增大而加大） |
| "GBN 出错只重传 1 帧" | × —— 重传出错帧及之后所有已发送帧 |
| "SR 接收方不需要窗口" | × —— SR 接收方也需要窗口来缓存乱序帧 |
| "W 越大利用率越高（GBN）" | 不一定——W 大也意味着出错时重传更多，$P_f$ 高时反而利用率更低 |

### 七、速记

```
无错时 GBN 和 SR 一样——都走流水线，管道塞满即 100%
有错时 GBN 拉回重传一连串（最多 W 帧），SR 只补出错那一个
利用率差就差在：GBN 分母多了 (W-1)P_f 的额外代价
图像形态相同 ≠ 效率相同
```

> **省流：** 图像上两者都是流水线，形态完全相同。但 GBN 出错后要重传出错帧及之后所有帧（最多 W 帧），利用率公式分母多了 $(W-1)P_f$；SR 只重传 1 帧，利用率只乘以 $(1-P_f)$。无错时公式一样，有错时 GBN 利用率显著更低——这是 GBN "后退 N"的代价。

## Q6 · 发送窗口大小、序号位数与协议约束

> 在以上的计算中，发送窗口的大小 $W_T$ 是否就决定了当前一个周期内流水线的数量。若已知帧序号的比特数 $n$，是否还需满足：GBN：$1 < W_T \le 2^n - 1$，SR：$W_R + W_T \le 2^n$。

**答：两个问题的答案都是肯定的。$W_T$ 就是同时在途的帧数上限（流水线深度）。序号比特数 $n$ 给出的窗口约束条件也是正确的。**

### 一、发送窗口 $W_T$ 就是流水线的"并发数"

```
时间 →
|帧0|帧1|帧2|帧3|帧4|帧5|帧6|帧7|
|<── 一个周期内同时在管道中的帧数 ≤ W_T ──>|
```

- $W_T = 1$：停等协议（只有 1 帧在管道中）
- $W_T > 1$：连续 ARQ（最高 $W_T$ 帧同时在管道中）
- $W_T \ge 1+2a$：管道被塞满，利用率可达 100%

> 利用率公式 $U = \frac{W_T}{1+2a}$ 中的 **$W_T$ 就是"一次最多能往管道里塞多少帧"**——$W_T$ 越大，同时飞在路上的帧越多，管道利用率越高。

### 二、序号比特数 $n$ 的约束——正确且完整

| 协议 | 约束条件 | 为什么 |
| :--- | :--- | :--- |
| **GBN** | $1 < W_T \le 2^n - 1$ | 避免新旧帧序号混淆，$W_T = 2^n$ 会死锁 |
| **SR** | $W_T + W_R \le 2^n$ | 发送窗口 + 接收窗口不能覆盖超过整个序号空间，否则新帧和重传帧无法区分 |

### 三、GBN：为什么 $W_T \le 2^n - 1$ 而非 $2^n$

```text
n = 2，序号空间 = {0, 1, 2, 3}，2^n = 4

假设 W_T = 4（违规）：
发送方发 [0,1,2,3]，全部丢失
接收方 expected_seq = 0，什么都没收到，不发 ACK
发送方超时重传 [0,1,2,3]          ← 同样是 0,1,2,3
接收方收到重传的 0 → expected_seq=1 → 回 ACK0
发送方收到 ACK0 → 认为"帧0 已确认" → 窗口滑动 → 发新的帧0！
                                            ↑
                        帧0 到底是重传的旧帧0还是新帧0？接收方无法区分！

正确：W_T ≤ 3（= 2^n - 1）
发送方发 [0,1,2]，全部丢失
超时重传 [0,1,2] → 接收方收帧0 → expected_seq=1 → ACK0
发送方收到 ACK0 → 窗口滑至 [1,2,3] → 发帧3（新序号，不冲突）
```

| $W_T$ 取值 | 结果 |
| :---: | :--- |
| $\le 2^n-1$ | 新旧帧序号不重叠，正常 |
| $= 2^n$ | 序号循环一周后无法区分新旧帧，**死锁或接收错误** |

### 四、SR：为什么 $W_T + W_R \le 2^n$

SR 的接收方也维护窗口来缓存乱序帧，两个窗口覆盖的序号不能重叠：

```
n = 2，序号空间 = {0, 1, 2, 3}

假设 W_T = 3, W_R = 3 → W_T + W_R = 6 > 4（违规）：
发送窗口：[0, 1, 2]
接收窗口：[3, 0, 1]（接收方期望从帧3开始）← 注意 0 和 1 同时出现在两个窗口！

接收方收到帧0 → 是发送方新发的帧0？还是重传的旧帧0？
→ 无法区分！因为 0 既在发送窗口也在接收窗口。
```

**正确配置**（$W_T + W_R \le 4$）：

```
通常取 W_T = W_R = 2^n / 2 = 2^(n-1)  ← 最均衡

n=2: W_T=2, W_R=2 → 发送窗口[0,1], 接收窗口[2,3] → 不重叠 
n=3: W_T=4, W_R=4 → 各取一半序号空间 
```

### 五、$W_T$ 的实际取值——三方约束

实际选择 $W_T$ 时要同时满足：

| 约束来源 | GBN | SR | 说明 |
| :--- | :--- | :--- | :--- |
| **序号空间** | $W_T \le 2^n - 1$ | $W_T \le 2^n - W_R$ | 硬上限 |
| **流水线利用率需求** | $W_T$ 越大越好，但 $\ge 1+2a$ 即达 100% | 同左 | 实用约束 |
| **出错代价** | $W_T$ 越大 → 出错重传越多 | 不受影响 | 权衡约束（仅 GBN） |

```
最优选择：W_T = min(硬上限, 1+2a)
        其中 1+2a 正好塞满管道即可，大了多余（GBN 中还有反作用）
```

#### 5.1 典型例题：$W_T = 8$ 需要几位序号？

```
场景：1+2a = 7.5 → 需要 W_T ≥ 8 才能塞满管道（100% 利用率）

n=3: 2^3 - 1 = 7 < 8  → 不够 ✗
n=4: 2^4 - 1 = 15 ≥ 8 → 够用 ✓

结论：n 至少为 4
```

> 核心认知：即使只需要 8 个窗口位置，$n=3$ 也只提供了 7 个——差 1 个就是不行。此时必须多花 1 位序号，$n=4$ 提供 15 个窗口位的冗余能力。多出的 7 个窗口位看似浪费，但序号位数的硬约束优先于"恰好塞满"的优雅——**$W_T \le 2^n-1$ 是铁律，不能商量**。

### 六、完整总结

| 问题 | 答案 |
| :--- | :--- |
| $W_T$ 决定流水线数量？ | 是——$W_T$ 是同时在管道中未确认帧的最大数量，直接决定流水线深度 |
| GBN 约束：$1 < W_T \le 2^n - 1$ | 对——$2^n-1$ 是硬上限，$=2^n$ 会导致序号混淆 |
| SR 约束：$W_T + W_R \le 2^n$ | 对——两窗口不能覆盖整个序号空间，通常取 $W_T = W_R = 2^{n-1}$ |
| 利用率公式中 $W_T$ 能用多大 | 不超过序号约束的硬上限，同时不必超过 $1+2a$（超额不提高利用率） |

### 七、速记

```
W_T 就是流水线深度，决定同时飞多少帧
n 位序号 → GBN 窗口最多 2^n-1，碰 2^n 就死锁
SR 两窗口和不超过 2^n，通常各取一半
W_T 够塞满管道就行，GBN 里大了反而出错代价大
```

> **省流：** 发送窗口 $W_T$ 就是流水线中同时在途的帧数上限，直接对应利用率公式的分子。$n$ 位序号 → GBN：$W_T \le 2^n-1$，SR：$W_T+W_R \le 2^n$（通常各取 $2^{n-1}$）。两个约束的本质目的相同——防止序号循环一周后新旧帧无法区分。

## Q7 · GBN 滑动窗口——ACK 乱序到达时的窗口滑动轨迹

> GBN 中，在发送了帧 0~6 后，收到了 ACK1、ACK2、ACK5 的确认。是不是先 ACK1 移动，再 ACK2 移动，最后 ACK5 移动？此时帧 6 是不是还没有到达接收方，而在接收方接到帧 6 后再次移动？

**答：理解完全正确。发送方窗口依次因每个 ACK 滑动，ACK5 的累积确认使它一次跳过三格。帧 6 作为窗口新下沿，悬而未决；待帧 6 到达接收方并返回 ACK6 后，发送方窗口再滑一次。两边窗口独立滑动，发送方滞后接收方一个 RTT。**

### 一、场景设定

```
发送方已发出：帧 0, 1, 2, 3, 4, 5, 6
接收方按序接收了：帧 0, 1, 2, 3, 4, 5（全部按序正确）
ACK1、ACK2、ACK5 正在返回路上...
```

> 关键前提：**ACK5 能够存在，说明接收方已经收到了帧 0~5 且全部按序**。GBN 接收方只对按序到达的帧发送 ACK——expected_seq 从 0 一路走到 6，意味着帧 0~5 全部按序收到。

### 二、发送方窗口的滑动过程（逐步追踪）

```
初始窗口：[0, 1, 2, 3, 4, 5, 6]  (假设 W_T = 7)

① ACK1 到达：
   含义：帧 0, 1 已确认
   窗口 → [2, 3, 4, 5, 6, 7, 8]
   ↑ 可发送新帧 7, 8

② ACK2 到达：
   含义：帧 0, 1, 2 已确认（前面的 ACK1 已滑过了 0,1）
   窗口 → [3, 4, 5, 6, 7, 8, 9]
   ↑ 可发送新帧 9

③ ACK5 到达：
   含义：帧 0~5 全部确认！（累积确认覆盖了 3, 4, 5）
   窗口 → [6, 7, 8, 9, 10, 11, 12]
   ↑ 一次性跳过三格（3, 4, 5 一并确认）
   ↑ 可发送新帧 10, 11, 12
```

### 三、帧 6 悬而未决——等待接收方确认

```
时刻 T：发送方窗口 = [6, 7, 8, 9, 10, 11, 12]

帧 6 的状态：已发出，ACK 未到，仍在"飞行中"
发送方对帧 6 的态度：已发但未确认，窗口下沿就是 6，等待中

接收方状态：expected_seq = 6，正等着帧 6 到来
```

**帧 6 到达接收方后：**

```
接收方：
  收到帧 6 → seq == expected_seq(6) → 匹配！→ 上交 → expected_seq = 7
  → 发送 ACK6（"0~6 全部收到"）

发送方收到 ACK6：
  窗口再次滑动 → [7, 8, 9, 10, 11, 12, 13]
  ↑ 帧 6 确认，窗口下沿变为 7
```

**所以你的理解是对的：发送方窗口先因 ACK5 滑到「下沿 = 6」，帧 6 悬着；等帧 6 到了接收方并返回 ACK6，发送方再滑一次。**

### 四、关键认知：两边窗口独立滑动，不同步

| 时刻 | 发送方窗口下沿 | 接收方 expected_seq | 说明 |
| :--- | :---: | :---: | :--- |
| 初始 | 0 | 0 | — |
| 发完帧 0~6 | 0（都未确认） | — | 发出去了但 ACK 还没回来 |
| 接收方收到帧 0~5 | 0 | 6 | 接收方已收 0~5，发 ACK5 |
| 发送方收到 ACK5 | **6** | 6 | 发送方才知道 0~5 已确认 |
| 帧 6 到达接收方 | 6 | **7** | 接收方先动，但发送方还不知道 |
| 发送方收到 ACK6 | **7** | 7 | 发送方跟上 |

> 发送方窗口和接收方窗口**不是同步的**——它们各自独立滑动，靠 ACK 这个"信使"来同步信息。发送方窗口的滑动比接收方**滞后一个 RTT**。

### 五、一个重要的易混淆点

> **接收方不会单独发出 ACK5 而不发 ACK3、ACK4**——在 GBN 中，ACK5 本身就是 0~5 的累积确认。如果接收方收到了 0,1,2 但没收到 3,4，它是不会送出 ACK5 的（它只会反复发 ACK2）。

所以你的场景中 ACK5 能被发出，就说明接收方已经按序收到了 0~5，帧 6 尚未到达时 expected_seq 已推进到 6。

### 六、速记

```
ACK 一个一个到，窗口一格一格移
累积确认覆盖多帧，窗口一次跳多格（ACK5 跳了 3,4,5）
帧 6 悬在窗口下沿，等它到接收方再回 ACK6
发送方滞后一 RTT，两边窗口不同步
```

> **省流：** 发送方按 ACK1→ACK2→ACK5 顺序收到确认，窗口依次滑到 [2,...] → [3,...] → [6,...]。帧 6 虽已发出但未确认，是窗口新下沿。待帧 6 到达接收方并返回 ACK6 后，发送方窗口再滑到 [7,...]。发送方与接收方窗口各自独立滑动，发送方滞后一个 RTT——两者的不同步正是滑动窗口协议要管理的核心问题。
