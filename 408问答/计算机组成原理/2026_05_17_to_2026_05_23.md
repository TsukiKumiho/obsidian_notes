## Q1 | 2026-05-17

**问题**：虚拟存储器是如何形成的，为什么虚地址空间远大于实地址空间，为什么引入了虚拟存储器就能够使得CPU访问的速度加快，虚拟存储器不只是一个地址空间吗，没包含任何数据，那么数据不还是从辅存里边访问的吗？它又不像是cache直接将主存中的数据副本在自己的存储空间中，而是只是一个利用主存和辅存构建的一个逻辑上连续的地址空间而已。还有，书上说虚拟存储器借鉴了cache的思想，将辅存中频繁访问的数据缓存在主存中。为什么是缓存，他不是只是一个地址空间吗？？？

**回答摘要**：

虚拟存储器 ≠ 仅地址空间，而是 **虚拟地址空间 + 主存 + 磁盘 + 页表 + 缺页中断机制** 构成的完整存储层次。

**虚实空间大小差异**：虚地址空间大小取决于 CPU 地址线宽度（如 32 位→4GB），物理内存取决于实际硬件。利用程序局部性原理，只需将活跃的工作集驻留主存，其余虚页留在磁盘，即可实现虚空间 ≫ 实空间。

**加速本质**：不是让单次访存变快，而是提升了系统吞吐量——程序无需全量装入内存即可运行（仅装入工作集），多道程序度提高，CPU 利用率上升。绝大多数访问命中主存（缺页率 <0.01%），平均访问时间 ≈ 主存延迟。

**Cache 思想的借鉴**：在存储层次中，主存本身就是磁盘的"Cache"——缓存磁盘中被频繁访问的页。虚地址空间中每一页的数据实际存放在磁盘上，主存中的物理页框是该数据的临时副本。命中时从主存读取（= Cache hit），缺页时从磁盘调入（= Cache miss），逻辑完全对应。

| 层次 | Cache | 虚拟存储器 |
| :--- | :--- | :--- |
| 上层（快/小） | Cache（SRAM） | 主存（DRAM） |
| 下层（慢/大） | 主存 | 磁盘 |
| 传输单位 | Block/Line | Page |
| 映射方式 | 直接/组相联/全相联 | 全相联 |
| 不命中处理 | 硬件 | OS 软件 |
| 命中率 | ~90%–99% | ~99.9%+ |
