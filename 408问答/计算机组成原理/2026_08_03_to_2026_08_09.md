### Q67 | 2026-08-05

**问题**：计算机组成原理中时序概念的辨析：机器周期、总线周期、总线事务等，它们的定义、层级关系与区别？

**回答**：

这组概念按"层级"拆开讲最清楚，从最小到最大逐个定义，再给对比表。

#### 一、先逐个定义（从最小到最大）

**1. 时钟周期（T 周期 / 节拍）**

- 机器中最基本的时间单位，由主频决定：$T = 1/f$
- 所有操作都在时钟脉冲驱动下进行，一个时钟周期就是一个节拍
- 例：主频 1GHz → 时钟周期 1ns

**2. 机器周期（CPU 周期）**

- 完成一个**基本操作**（取指令、读主存、写主存、中断响应等）所需的时间
- 通常规定为**存取周期或存取周期的整数倍**
- 经典划分的四个机器周期：**取指周期、间址周期、执行周期、中断周期**
- 为什么拿存取周期当基准？因为 CPU 的基本操作大多要访存，而访存是最慢的一环，用它作基准最省事

**3. 指令周期**

- 取出并执行**一条指令**所需的全部时间 = 若干机器周期之和
- 最简单的指令也要 `取指周期 + 执行周期`（2 个机器周期）；间接寻址会多一个间址周期，响应中断会多一个中断周期
- 指令周期长短**不固定**，因指令而异——这是它和机器周期最大的区别

**4. 存取周期（存储周期）**

- 连续两次独立访问存储器所需的最短时间间隔 = 存取时间 + 恢复时间
- DRAM 里恢复时间来自读出放大器的恢复和刷新需求，所以存取周期 > 单纯读出一个数据的时间

**5. 总线周期**

- 总线完成**一次数据传输**（传一个字或一个数据块）所需的时间
- 一次总线周期通常包含：地址相位 + 数据相位（读操作还可能插入等待周期）
- 同步总线下总线周期 = 固定个数的时钟周期；异步总线下靠握手，周期长度可伸缩

**6. 总线事务**

- 从请求方**发起请求到本次传输完整结束**的整个过程，可能跨越**多个总线周期**
- 典型阶段：请求 → 仲裁 → 寻址 → 传输 → 结束
- 关键区分：单字传输时 `1 个事务 = 1 个总线周期`；**突发传输时 `1 个事务 = 1 个地址周期 + n 个数据周期`**（比如 PCI 总线一次突发读可以连传多个数据）

**7.（补充）微周期**

- 执行一条**微指令**所需的时间，通常 = 1 个时钟周期
- 微指令在一个节拍内完成，所以微周期是微程序控制方式下的最小时间单位

#### 二、包含关系图

```text
指令周期（不固定，随指令变）
├── 取指周期   ┐
├── 间址周期   │  ← 都是"机器周期"（固定）
├── 执行周期   │     每个机器周期 = 若干时钟周期
└── 中断周期   ┘
        ↑
   时钟周期（节拍，最底层单位）

总线事务（一次完整主-从交互）
├── 请求/仲裁阶段
├── 地址相位
└── 数据相位（突发 = 多个数据相位）  ← 一个事务可含多个总线周期
```

#### 三、辨析对比表

| 维度 | 时钟周期 | 机器周期 | 指令周期 | 总线周期 | 总线事务 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 谁的概念 | CPU 时钟 | CPU 内部操作 | CPU 执行指令 | 总线传输 | 总线一次交互 |
| 组成 | 最小单位 | 若干时钟周期 | 若干机器周期 | 若干时钟周期 | 一个或多个总线周期 |
| 长短 | 固定 | 固定 | **不固定** | 同步固定/异步可变 | 随传输量变 |
| 基准 | 主频 | 存取周期 | 机器周期 | 时钟/握手 | 总线周期 |
| 是否可缺省 | — | 取指周期必有 | — | 每个事务必有 | — |

#### 四、最容易混的几组

**① 机器周期 vs 总线周期**

- 机器周期是 **CPU 视角**：完成一个基本操作；总线周期是 **总线视角**：完成一次传输
- CPU 访存时两者时间上重合（取指 = 发地址 + 收数据，正好一次总线传输），但寄存器间运算的机器周期里**根本没有总线周期**
- 一句话：**机器周期"借用"了存取周期做基准，总线周期是总线上的实体传输**，不是一回事

**② 总线周期 vs 总线事务**

- 事务是"一整件事"（请求到完成），周期是"传一次数据"
- 单字传输：相等；突发传输：`1 事务 = 1 地址周期 + 多个数据周期`
- 所以突发传输提高效率，本质就是**一个事务里摊销了多次寻址开销**

**③ 机器周期 vs 存取周期**

- 不是相等，是"**约等于或整数倍**"
- 因为一个机器周期内完成的基本操作（取指/访存）对应一次完整访存，所以定成存取周期最合理；但机器周期是 CPU 时序单位，存取周期是存储芯片物理参数

**④ 为什么指令周期不固定**

- 时钟周期、机器周期都是**硬件固定**的；指令周期却取决于指令复杂程度
- NOP 指令 = 2 个机器周期；访存指令的执行周期里还要再访存一次，可能 3~4 个机器周期

#### 五、完整示例

假设主频 100MHz，机器周期 = 4 个时钟周期，某指令 = 取指 + 执行（各 1 个机器周期）：

```text
时钟周期 T = 10ns
机器周期   = 4T = 40ns
指令周期   = 2 × 40ns = 80ns

|←── 指令周期 80ns ──→|
|← 取指周期 40ns →|← 执行周期 40ns →|
| T1| T2| T3| T4 | T1| T2| T3| T4 |   ← 每格 10ns
```

如果这条指令是间接寻址，指令周期 = 3 个机器周期 = 120ns。

#### 六、408 真题视角

- 常考问法："机器周期内节拍数由什么决定""指令周期 = 几个机器周期""同步总线一个总线周期含几个时钟周期"
- DMA 周期挪用：每次挪用 = **一个总线周期**（传一个字），不是整个事务
- 突发传输必配多体交叉：一个事务多个数据周期，连续地址要落在不同存储体才能不停顿

> **省流：** 层级是 **时钟周期 → 机器周期 → 指令周期**（CPU 侧，固定→固定→不固定）；**总线事务 ⊇ 总线周期**（总线侧，事务是"整件事"，周期是"传一次"）。机器周期以存取周期为基准，总线周期以时钟为基准；CPU 访存时两者重合，但概念归属不同。间接寻址多一个间址周期、响应中断多一个中断周期——这是指令周期不固定的两大来源。

### Q68 | 2026-08-05

**问题**：对比程序中断方式和 DMA 方式，特别是它们被响应的时机；另外，有人说"DMA 的响应可发生在一个总线事务后（只要当前 CPU 未占用总线即可，因为 DMA 请求的是总线控制权）"，如何理解？

**回答**：

这个问题分两部分：先对比程序中断与 DMA 的完整区别，再专门辨析"响应时机"的精确表述。

#### 一、一句话本质

- **程序中断方式**：外设每准备好一个数据就中断 CPU，CPU **执行中断服务程序（ISR）**逐字搬运数据——数据经过 CPU。
- **DMA 方式**：DMA 控制器**直接控制外设↔主存**传送，数据不经过 CPU；CPU 只在传送前初始化、传送后收一次中断通知。

#### 二、响应时机（重点）

这是两者最核心的区别，三个检测点（对应 Q62）：

```text
异常  → 指令执行中检测
中断  → 指令执行结束时检测（指令周期边界）
DMA   → 总线周期结束时检测（更细的粒度）
```

**程序中断的响应时机：**

```text
|←────── 指令 1 ──────→|←────── 指令 2 ──────→|
                        ↑
                  当前指令执行完毕
                  (IF=1 且有请求 → 响应)
                  保存现场 → ISR 传一个字 → 恢复现场 → 返回
```

- 响应条件是"**一条指令完整执行完**"（取指+间址+执行全结束）
- 为什么？中断响应要打断程序流、保存断点、执行 ISR，必须在一个**指令边界**才能安全切换
- 代价：每传一个字都要完整走一遍"保护现场→搬数据→恢复现场→中断返回"，开销巨大

**DMA 的响应时机：**

```text
|← 总线周期 →|← 总线周期 →|← 总线周期 →|
             ↑          ↑
      CPU 在当前总线周期结束时
      采样 HRQ，让出总线一个周期
      DMA 控制器直接传一个字
```

- 响应条件是"**当前总线周期结束**"（几个时钟周期），**不必等指令结束**
- 为什么可以这么快？DMA 要的只是**总线使用权**，不占用 CPU 的寄存器、ALU，CPU 让出一个总线周期就能继续跑（周期挪用）
- 代价：几乎为零——CPU 不用保存现场，硬件直接完成传送

#### 三、完整对比表

| 维度 | 程序中断方式 | DMA 方式 |
| :--- | :--- | :--- |
| 传送单位 | 一个字/字节 | 数据块（连续多个字） |
| 数据通路 | 外设 → CPU → 主存（经 CPU） | 外设 ↔ 主存（不经 CPU，只经总线） |
| 谁执行传送 | CPU 执行 ISR 指令 | DMA 控制器（硬件） |
| **响应时机** | **指令结束时** | **总线周期/事务结束时，总线空闲则立即** |
| 响应粒度 | 粗（一条指令） | 细（一个总线周期） |
| CPU 参与 | 每字都要中断、保存/恢复现场 | 仅传送前初始化 + 块结束时一次中断 |
| 中断频率 | 每传一个字中断一次 | 整块传完才中断一次 |
| 优先级 | 较低（可被更高优先级中断抢占） | **高于普通中断**（不及时响应会丢数据） |
| 适用设备 | 低速（键盘、打印机字符） | 高速（磁盘、网卡） |

#### 四、为什么 DMA 响应更"及时"

| 原因 | 说明 |
| :--- | :--- |
| 检测点更细 | 中断等**指令**边界，DMA 等**总线周期**边界（指令 ≥ 1 个机器周期 = 多个总线周期） |
| 不需要 CPU 状态切换 | 中断要保存断点/现场；DMA 只是借总线，CPU 寄存器一概不动 |
| 优先级设计 | DMA 请求优先级高于中断——磁盘/网卡数据**持续到达**，晚响应一拍就可能 overrun（数据覆盖丢失） |

#### 五、几个易混点

**① DMA 也用中断，但角色不同**
- 程序中断方式：中断是**传送手段**（每次传送都靠中断）
- DMA 方式：中断是**通知手段**（整块传送结束，DMA 控制器发一次中断告诉 CPU"干完了"）——对应 Q65 里"传送完毕→撤 HRQ→发中断请求"

**② "DMA 传送不经过 CPU"≠"不经过总线"**
- 数据外设→主存直接走系统总线，绕过的是 CPU 内部的寄存器/ALU，不是总线

**③ 响应时机对应的请求信号不同**
- 程序中断检测的是 **INTR**（中断请求线）
- DMA 检测的是 **HRQ**（总线请求，Q65：外设 DREQ → 控制器锁存 → 发 HRQ）

**④ 中断处理过程中 DMA 还能插进来**
- DMA 请求优先级高于中断：即使 CPU 正在执行 ISR，DMA 也可以在总线周期结束时拿走总线（周期挪用），ISR 只是暂停访存而已

#### 六、"响应可发生在一个总线事务后"如何理解

这个说法**正确且更精确**，与"总线周期结束时检测"不矛盾——区别是"硬件采样点"与"实际让出时机"：

| 当前总线状态 | 能否响应 | 说明 |
| :--- | :--- | :--- |
| **空闲**（CPU 内部运算、未访存） | **立即响应**，零等待 | 没有"当前事务"可等，HRQ 一到就放行 |
| CPU 占用中（单字传输） | 等**当前总线周期/事务结束** | 单字事务 = 1 个总线周期，两者重合 |
| CPU 占用中（突发传输） | 等**整个总线事务结束** | 突发事务中间不能让，否则破坏传输连续性 |

```text
情况一：总线空闲（CPU 内部运算）
  外设 DREQ → DMA 发 HRQ ──────────→ CPU 立即响应（0 等待）

情况二：CPU 单字总线传输
  |←── 一个总线事务（=1总线周期）──→|
                                ↑ 事务结束 → 响应

情况三：CPU 突发传输
  |←地址相→|←数据1→|←数据2→|←数据3→|
                                    ↑ 整个事务结束才响应
```

**两种表述的关系：**

- "**总线周期结束时检测**"：CPU 硬件的**采样点**——每个总线周期末统一看一眼 HRQ 线（Q62 的说法，真题视角）
- "**一个总线事务后响应**""**总线空闲立即响应**"：**实际让出总线的最早时机**——采样到了不代表立刻能让，还要等当前占用总线的事务走完；若采样时总线本来就空，当场响应

一句话：**检测在"周期末"，让出在"事务末"，总线空着就直接响应。** 单字传输时"周期末"和"事务末"是同一时刻，所以两种表述经常混用，并不冲突。

**为什么中断必须等指令边界、DMA 不用？**

| | 程序中断 | DMA |
| :--- | :--- | :--- |
| 请求的资源 | CPU 执行权 | 总线控制权 |
| 响应时机 | **必须**指令执行完毕 | **只要 CPU 未占用总线即可**（否则等当前事务结束） |
| 最坏等待 | 一条指令（可能几个机器周期） | 一个总线事务（突发时才较长；空闲则 0 等待） |
| 为什么 | 要安全保存断点、切换程序流 | 不打断程序流，只借用总线 |

#### 七、与已有记录的联动

- **Q62**："DMA 请求在总线周期结束时被检测"——指 HRQ 的采样点，正确，但那是"检测"不是"响应"
- **Q65**：DMA 请求分两级（DREQ→HRQ），HRQ 是发给 CPU 要总线的——正因为它要的是总线，"总线空闲即响应"才成立
- **Q67**：总线事务 ⊇ 总线周期（突发 = 1 地址周期 + n 数据周期）——正是这个包含关系，让"响应在事务后"比"响应在周期后"更精确
- **Q63**：周期挪用模式每传一个字归还总线，响应粒度就是"一个事务/周期"；停止 CPU 访存模式则是一次响应后连续占用

> **省流：** 程序中断响应在**指令结束**（要保存现场、执行 ISR 逐字搬数据，慢）；DMA 响应在**总线周期/事务结束**，总线空闲则**立即响应**（只要总线，硬件直传，快）。"周期末检测"是采样点，"事务后响应"是实际让出时机，两者不冲突。DMA 优先级高于中断是为防止高速设备数据丢失；DMA 传送结束后才用一次中断通知 CPU。对应 Q62：异常=指令中、中断=指令末、DMA=总线周期末。

### Q69 | 2026-08-05

**问题**：Cache 在不同映射方式下各字段（Tag、Index、Offset）的组成和分布；指令 Cache 与数据 Cache 的区别；Cache 总容量如何计算？另外辨析：这些"字段"到底是谁的字段？Cache 块数据指什么？标记位包含行号/组号/块内地址吗？

**回答**：

这个问题串起 Cache 计算题的完整骨架。先给一条主线把全部概念顺一遍，再逐块展开。

#### 一、总纲：一次 Cache 访问的全流程（先顺一遍）

从 CPU 发出一个地址开始，五步走完：

```text
① CPU 发出主存地址（如 32 位）
        ↓
② 字段划分：按映射规则拆成 [ Tag | Index | Offset ]
        ↓
③ Index 译码 → 选中 Cache 中一组/一行（位置即索引）
        ↓
④ Tag 比较 + 有效位=1 → 命中；否则缺失调块
        ↓
⑤ Offset 在块数据内选字节 → 返回数据
```

| 步骤 | 用的东西 | 存储/使用性质 |
| :--- | :--- | :--- |
| ② | 地址被拆成三字段 | 逻辑划分 + 硬件按位接线（**不作为数据存储**） |
| ③ | Index 位 | 译码选行（**不用存**，位置即索引） |
| ④ | 行内 Tag 与地址 Tag 比较 | **Tag 是唯一存进 Cache 行的地址部分** |
| ⑤ | Offset 位 | 块内选字节（**不用存**，现用现取） |
| 数据 | 缺失时从主存搬 32B | **块数据** = 真实数据，存在行里 |

**一条主线**：地址是"货单"，字段是"分栏规则"，Cache 行是"货架格子"——分拣机（Cache 控制器）按分栏规则工作：Index 找货架、Tag 验货、Offset 取货；货架格子里只贴"货号高位"（Tag）和"有效/脏"标签，不重贴分栏规则。

#### 二、字段 = 主存地址的位划分

**字段划分的对象是"主存地址"**：CPU 发出的访问地址按映射规则拆成三段。

```text
主存地址（32 位）= [ Tag | Index(组号) | Offset ]
                      t 位    s 位       b 位
t + s + b = m
```

- 不是 Cache 里存的字段，也不是主存里存的字段——**主存单元里全是数据，Cache 行里只存 Tag**
- 是"逻辑上的划分"没错，但**硬件真实按这些位工作**：Index 位接译码器选行、Tag 位接比较器判命中、Offset 位接多路选择器选字节——字段作为**信号**被使用，不作为**数据**被存储
- 三种映射的区别 = **同一个地址的不同切法**（见下节），不是换地址，而是换"怎么拆这个地址"

#### 三、三种映射的字段分布

**① 直接映射（r = 1）**

```text
|←────── Tag ──────→|← Index →|← Offset →|
       t = m−s−b       s = log2(行数)   b
```

- Index = **主存块号 mod 行数**，一个块只有唯一位置
- 无需替换算法，但易冲突抖动（Q27 的 2016 真题就是直接映射）

**② 全相联（S = 1）**

```text
|←─────────── Tag ───────────→|← Offset →|
        t = m − b               b
```

- **没有 Index 字段**（s = 0），块可放任意行
- Tag 全比较（所有行并行比较），硬件成本最高，需替换算法

**③ 组相联（r 路，共 S 组）**

```text
|←────── Tag ──────→|← 组号 →|← Offset →|
       t = m−s−b       s = log2(S)   b
```

- 组号 = **主存块号 mod 组数**；组内 r 行全相联（组内并行比 Tag）
- 组数 S = 总行数 / r；组内需替换算法（LRU 等）

**统一视角**：直接映射 = 1 路组相联；全相联 = 组数为 1。真题"n 路组相联"公式全覆盖：

| 参数 | 公式 |
| :--- | :--- |
| 块内偏移 b | log2(块大小 B) |
| 组数 S | Cache 数据容量 ÷ (r × B) |
| 组号位数 s | log2(S) |
| Tag 位数 t | m − s − b |

#### 四、Cache 行的组成：块数据、Tag、标志位

**① 块数据是什么**

- = 从主存搬过来的**真实数据本身**，大小等于主存块大小（如 32B）
- 缺失时把主存连续 32B 整体调入 Cache 行的"数据部分"（Q27 中 `a[0]~a[3]` 四个 int 就是块数据）
- 不是地址、不是标记，就是程序要读写的数

**② Cache 行里存什么**

```text
Cache 行 = [ 块数据 | Tag | 有效位 | 脏位(写回时) ]
```

- **没有**组号、行号、块内地址
- "标记"叫法有歧义：有的教材把 **Tag** 叫"标记"，有的把 **有效位/脏位等标志位**叫"标记位"。统一：**Tag = 地址高位（来自地址划分，t 位）**；**标志位 = 有效位/脏位/LRU 等控制位（额外存储）**

```text
地址（用于访问）:   [ Tag | 组号 | 块内地址 ]
                      ↓      ↓        ↓
Cache 行（用于存储）: 数据 + Tag + 有效位/脏位
                      ↑      ↑
                  真实数据  只有这个来自地址
```

**③ 为什么组号/块内地址不用存**

- 组号：位置本身就是索引（数据都放那行了，再存一份冗余）
- 块内地址：命中后现用现取（用地址低 b 位选字节），不参与命中判断
- 命中流程：组号译码选组 → 组内 Tag 并行比较 → 相同且有效位=1 命中 → 低 b 位选字节

**④ 补充：主存地址没有"行号"字段**

- 直接映射时 Index 选的就是行（行号=组号）
- 组相联时 Index 只选组，组内哪一行由 **Tag 并行比较**决定，行号不体现在地址里

#### 五、Cache 总容量计算

**两个容量要分清：**

```text
数据容量 = 组数 × 路数 × 块大小 = S × r × B
总容量   = 行数 × (块大小×8 + Tag + 有效位 + 脏位)   ← 单位 bit
```

**例题**：按字节编址，主存地址 32 位，Cache 数据容量 64KB，块大小 32B，4 路组相联，写回法。

| 项目 | 计算 | 结果 |
| :--- | :--- | :--- |
| b | log2(32) | **5 位** |
| 行数 | 64KB ÷ 32B | 2048 行 |
| 组数 S | 2048 ÷ 4 | 512 组 |
| s | log2(512) | **9 位** |
| t | 32 − 9 − 5 | **18 位** |
| 每行位数 | 32×8 + 18 + 1 + 1 | 276 bit |
| 总容量 | 2048 × 276 | 565,248 bit ≈ **69 KB** |

**常见陷阱：**
- 题问"Cache 容量"没写"数据容量"时，按**总容量**算（含 Tag/标志位）
- 组相联先算**组数**再取对数，别拿行数当组数
- 按字编址时 b 变小，多出的位全进 Tag（Q28，数据位不变）

#### 六、指令 Cache vs 数据 Cache

**概念**：L1 分离成 I-Cache / D-Cache → 哈佛结构；统一 Cache → 冯·诺依曼结构。现代 CPU 通常 **L1 分离、L2/L3 统一**。

| 维度 | 指令 Cache | 数据 Cache |
| :--- | :--- | :--- |
| 内容 | 指令流 | 操作数 |
| 访问特征 | 顺序为主，局部性极好 | 随机性大（数组、指针） |
| 是否可写 | **只读** | 可读写 |
| 脏位 | **不需要** | 写回时需要 |
| 写策略 | 无 | 写直达/写回 |
| 一致性 | 天然一致 | 需处理（写策略 + 多核/DMA 一致性） |

**为什么分离（408 高频考点）：**
- **取指和取数可同时进行**——两条独立通路，支撑流水线并行，这是根本动机
- 指令、数据特征不同，可分别优化（容量分配、预取、替换策略）
- I-Cache 只读 → 省掉脏位和写策略，硬件更简单

**代价：**
- 容量固定分割，指令/数据负载不均时利用率低
- 总容量相同时，统一 Cache 更灵活

#### 七、与已有记录的联动

- **Q22**：行中只存 Tag+数据+标志位，不存 Index/Offset
- **Q28**：行位数公式（数据+Tag+有效位+脏位），字节/字编址只影响 Tag
- **Q27**：直接映射缺失率计算——字段划分是"块号 mod 行数"选行的基础
- **Q30**：分页靠查表、Cache 靠地址字段"算"出位置——字段分布就是"算"的硬件基础
- **Q64**：DMA 写主存导致 D-Cache 不一致——数据 Cache 才有一致性问题

#### 八、五连问自查（检验是否顺了）

| 问题 | 答案 |
| :--- | :--- |
| 字段是谁的？ | **主存地址的位划分**（解读规则），不是任何存储器的内容 |
| Cache 行里存什么？ | 数据 + Tag + 有效位/脏位，**不存 Index/Offset/行号** |
| 为什么全相联 Tag 最长？ | 没有 Index 字段，t = m − b |
| 为什么直接映射不用替换算法？ | 每个块位置唯一（块号 mod 行数） |
| 总容量含什么？ | 数据 + Tag + 标志位（有效位、脏位等） |

> **省流：** 一条主线——**地址是货单、字段是分栏规则、Cache 行是货架格子**。字段 = 主存地址的位划分（t = m − s − b）：全相联无 Index（s=0）、直接映射 r=1、组相联 s=log2(组数)；字段逻辑上划分、硬件真实接线使用，但不作为数据存储。Cache 行 = 数据块 + Tag + 标志位，Index/Offset 靠"位置"和"现用现取"解决。总容量 = 行数 × (数据+Tag+标志位)，题问"容量"默认总容量。I/D Cache 分离 = 哈佛结构，为了**取指取数并行**；I-Cache 只读 → 无脏位、无写策略；L2/L3 通常统一。
