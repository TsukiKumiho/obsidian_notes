## 二、按章节逐题汇总

### 第 1 章 · 操作系统概述（Q1–Q3, Q5, Q6, Q9–Q11）

| Q# | 类型 | 关键词 | 问题 | 核心结论 |
| :---: | :---: | :--- | :--- | :--- |
| Q1 | 概念问题 | 系统调用/系统命令 | 系统调用是否等同于系统命令？ | 不是。系统调用是内核原子功能单元（核心态），系统命令是可执行程序（用户态），一条命令通常调用多个系统调用 |
| Q2 | 概念问题 | 系统调用发生位置 | 系统调用到底在哪里发生？能否说在用户态发生？ | 可以。408 真题定调：系统调用"在用户态发生"指用户态执行陷入指令发起请求；处理阶段转入内核态。发起在用户态，处理在内核态 |
| Q3 | 概念问题 | 特权指令 | 哪些指令/事件不能在用户态执行？ | 用户态只能做计算、访自己内存、发系统调用。I/O、关中断、改页表、改控制寄存器、停机等均为特权指令，必须在核心态执行 |
| Q5 | 总结 | 硬件/OS 分工 | 系统调用/中断/异常中，硬件和 OS 分别做了什么？ | 硬件：保存 PC/PSW、切换栈、查向量表、跳转 ISR。OS：保存通用寄存器、执行处理逻辑、恢复上下文、中断返回。分工表覆盖三种事件 |
| Q6 | 概念问题 | 中断/子程序/系统调用/库函数 | 中断 vs 子程序调用有何区别？系统调用 vs 库函数有何区别？ | 中断：硬件触发，异步，内核态处理。子程序：软件调用，同步，同态。系统调用：跨边界（用户→内核）。库函数：全程用户态 |
| Q9 | 概念问题 | 外核 Exokernel | 什么是外核？与微内核有何区别？ | 外核只做资源隔离与复用（不抽象），将硬件资源直接暴露给应用层库 OS。微内核做最小化抽象+IPC 通信。外核性能最高、隔离靠硬件 |
| Q10 | 概念问题 | 用户态/内核态 | 用户态与内核态的本质区别是什么？如何切换？ | 本质区别：CPU 特权级别决定可执行的指令集合。切换方式：用户→内核通过 trap/中断/异常；内核→用户通过中断返回指令。PSW 中 mode bit 控制 |
| Q11 | 概念问题 | VMM 类型/虚拟化 | 两种 VMM（Type 1 vs Type 2）中 Guest OS 的用户态与内核态如何运行？ | Type 1（裸机型）：Guest OS 内核运行在非根模式（deprivileged），特权指令被 trap 到 VMM。Type 2（宿主型）：Guest OS 是宿主机上的用户进程。两种情况下 Guest OS 的"内核态"都被降权 |

### 第 2 章 · 进程管理（Q7, Q8, Q12–Q15）

| Q# | 类型 | 关键词 | 问题 | 核心结论 |
| :---: | :---: | :--- | :--- | :--- |
| Q7 | 概念问题 | 时钟中断 ISR | 时钟中断服务程序需要更新哪些内容？ | 更新：①当前进程时间片计数器 ②系统全局时间 ③定时器链表检查与唤醒 ④CPU 使用时间统计 ⑤就绪/运行队列调整（时间片耗尽触发调度） |
| Q8 | 概念问题 | 信号 Signal | 信号（Signal）的核心概念是什么？ | 信号是 OS 的软件中断机制——异步通知进程某事件发生。生命周期：生成→递送→处理（默认动作/忽略/用户注册 handler）。sigaction 可精确控制处理行为 |
| Q12 | 概念问题 | KLT/一对一模型 | 纯内核级线程（KLT）与组合方式一对一模型（ULT+KLT）有何区别？ | 核心区别仅在于用户空间是否有线程库层。纯 KLT：App 直接 syscall 创建 KLT。一对一：线程库维护 ULT 描述符，再通过 clone() 创建对应 KLT。两者的内核 TCB 和调度行为完全一致 |
| Q13 | 总结 | 进程阻塞事件 | 哪些事件会导致进程从 Running → Blocked？ | 9 类阻塞事件：I/O 请求、资源申请失败、等待子进程、进程间同步、消息通信、定时/睡眠、缺页中断、用户输入、网络 I/O。Run→Blocked 必为主动调用。**部分事件有条件**：申请临界资源仅在被占用时阻塞，read() 仅在 cache miss 时阻塞 |
| Q14 | 概念问题 | 读磁盘本质 | 进程读磁盘是激活另一个进程，还是进程自带的能力？ | 都不是。读磁盘 = 进程通过 read() 系统调用委托 OS 内核完成。三角色：进程发起请求（用户态）→ 内核驱动硬件（内核态）→ 磁盘控制器执行 DMA 传输（硬件）。进程在 I/O 期间 Blocked，不占 CPU |
| Q15 | 概念问题 | ULT 双层管理/三种线程模型 | 用户级线程中线程管理在用户空间，但进程仍由内核创建——正确吗？ | 完全正确。进程是内核创建的"容器"（PCB），线程是用户空间线程库创建的"内容"（TCB）。补全三种线程模型对比：纯 ULT（多对一，切换快但一阻塞全进程陪葬）、纯 KLT、一对一（取两者之长）。ULT 致命缺陷：一个线程阻塞系统调用 → 内核阻塞整个进程 |
